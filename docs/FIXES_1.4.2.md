# 1.4.2 播放等待与歌词样式修复

## 音源切换

原实现按来源串行搜索和解析，每个来源可等待 12 秒；初始取流还可等待 15 秒，连接失败后再完整重试一次。多个慢源会把等待时间累加。

改为并行匹配启用来源，每个来源的搜索、解析和音频验证共用 6 秒预算。已有可用音频时，最多等高优先级来源额外 200 ms；仍保留网易云、QQ、酷狗、酷我、B站、其他的优先顺序。取流 API 成功不足以证明能播放，因此用少量 Range GET 校验实际音频头，并并行选择可连接的 CDN。取消会关闭网络调用，失败候选不重复，取消的未完成候选可在下一次恢复时继续尝试。原有录音匹配、独立缓存、切歌隔离及队列跳过规则保留。

回归使用可控时钟和模拟 HTTP 服务：高优先级来源停滞时，100 ms 就绪的备用来源在 300 ms 被选中；全部来源停滞时共等待 6 秒。以上是测试场景的策略耗时，不是真机网络或音频输出测量，也不承诺跨源零间隙播放。

## 歌词样式

确认并修复两条会把动态视界变成普通歌词的路径：

1. 较旧 WebView 缺少 `Array.at`，而三个 Folia 引擎都调用了它。Chrome 90 构建目标只转换语法，不补运行时 API。浏览器测试移除该 API 后，原包实际报 `at is not a function` 并进入失败状态。新包在引擎加载前补充兼容实现，同一测试可以启动全部三个引擎。
2. 减少动效或系统动画关闭时，Android 桥接层直接返回原生歌词组件。现在保留选中的引擎，使用其静态模式；画面仍能按歌曲进度切换。

选择样式后记录歌词页为下次打开页面，设置提供「查看当前歌曲效果」。渲染失败时显示明确提示和重新加载按钮；更换样式或画质会创建新的 WebView，避免失败状态一直遮盖后续选择。

回归覆盖真实设置保存到播放器页面、减少动效、渲染进程失败后重建，以及三个实际 WebGL 引擎的差异、字幕时间、暂停、seek、连续切换和旧 WebView 兼容。Robolectric 覆盖 Android API 31/34；浏览器截图来自实际 WebGL 渲染，不是手机实测。
