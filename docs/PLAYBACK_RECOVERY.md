# 统一搜索、播放恢复与服务端 B站会话

1.4.1 将音源作为歌曲的播放来源。搜索页展示合并后的歌曲列表，不再提供平台筛选。相同歌名、完整歌手名单且时长接近的跨平台结果合并；保留现场版、翻唱、时长差异和未知歌手，避免错误替换录音。代表来源按网易云 → QQ → 酷狗 → 酷我 → 哔哩哔哩 → 其他排列。

1.4.2 修复逐个平台等待造成的长时间停顿。播放地址失效或实际媒体加载失败后，同时搜索其他已启用来源，包括排在原来源之前的平台。各平台搜索、取流和验证合计最多等待 6 秒，而非每个平台累加；第一个验证成功的结果最多额外等 200 ms，让更高优先级的来源完成。B站低码率音轨与其他来源并行，不阻塞整轮。各来源最多匹配三个同录音候选；一次请求最多七个平台，不进行后台无限探测。

取流接口返回成功后，还会通过 Range GET 检查最多 64 字节的真实音频头，拒绝 HTTP 错误、错误 Range、HTML/JSON 和未知文件头。等价 CDN 地址最多并行验证三个，每个请求总超时 3 秒，选中后取消其他请求并关闭响应；只缓存验证成功的地址。初始取流解析预算 4 秒，播放连接超时 2.5 秒、读取无数据超时 4 秒；不再先对同一失败来源完整重试一次。网络、系统调度和新解码器缓冲仍可能造成短暂停顿，不保证跨源无缝播放。

每次选择记录已搜索平台和已失败的曲目/音质。尚未完成但因竞速被取消的候选保留再次尝试资格，已验证备用结果最多保留 90 秒。替换保持音乐库身份，以新的 URI、解码器、字节缓存及实际录音信息继续播放，不将其他音频文件拼接到旧字节偏移。

一首歌所有候选均失败后，按队列顺序或随机顺序跳过。单曲循环中的失败歌曲也会跳过；整轮队列都不可用时暂停，避免循环请求。暂停、手动切歌或重试会取消旧请求；播放页显示正在换源并允许暂停。成功播放或用户重新选择后允许再次尝试。完全离线且没有完整缓存时仍无法播放。

## 构建与凭证边界

- GitHub CI 强制清空全部私有音源字段。公开构建默认启用免费公开来源及聚合补充；来源是否能播放仍取决于上游返回，不保证所有平台或版权曲目可用。
- 本地包可注入 Solara 服务配置、B站 CF 入口及专用服务访问密钥。配置文件受 Git 忽略，私有 APK 不作为公共 GitHub 资产。
- 应用已删除扫码入口、登录流程及账号会话存储。升级时删除旧版的加密会话文件和 Android Keystore 会话密钥。
- B站 Cookie 仅保存在自建 CF Worker 的 `BILI_COOKIE` Secret；另配 `KINARA_CLIENT_TOKEN` Secret 保护服务。缺少访问密钥的私有部署拒绝请求。Cookie 不进入 APK、源码、响应、日志或 CDN 请求。
- CF 只向官方 B站 API 发送账号 Cookie。私有请求使用官方 WBI 签名；搜索返回歌曲信息，解析返回本服务内的流地址。
- 播放和下载可以使用 15 分钟、绑定 BVID/分集/音质的 HMAC 流凭证，避免将长期服务密钥交给系统 DownloadManager。流凭证不能查询搜索接口，也不能改为另一首曲目。Android 的媒体客户端逐跳校验域名并移除原目标的访问密钥。

## 2026-10-19 验证与限制

官方扫码已成功；开发机当时的官方请求通过搜索、音频解析和 1 KB 音频读取。随后会话转存 CF Secret，本机副本与临时内存已清理。

同一会话在 CF 上的实际搜索和解析返回 B站 `-412`；WBI 请求也未解除此限制。这说明当前 CF 出口仍被上游限制，不能以 Cookie 保存成功宣称 B站已经恢复。客户端保留公开请求和其他来源的回退，服务明确返回错误。需要在可被上游接受的服务环境中再次验证搜索、解析和音频读取；不伪造空结果，也不无限重试。

回归覆盖来源顺序、从低优先级回到高优先级、同源多个候选、版本误匹配、超时、取消、缓存隔离、队列全部失败、随机/单曲循环，以及 Worker 鉴权、Cookie 隔离、流凭证防篡改和重定向边界。真实设备的扬声器、蓝牙和后台播放仍需设备验收。
