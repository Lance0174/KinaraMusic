这次交付是手机与桌面大屏的 HTML 交互原型。确认后，按官方 Miuix Compose 组件落地正式 App。

当前阶段尚未添加 Android 依赖、构建或发布新版 APK。现有播放器与签名保留。预览播放按钮只驱动演示时钟，实际播放性能会在 Android 上测量。

你可以确认的变化

  • Miuix 大标题、16 dp 分组卡片、蓝色控件与更清晰的播放页层级；可选深色与工业外观。
  • 搜索按歌曲汇总，不分音源页面。优先网易云 → QQ → 酷狗 → 酷我 → 哔哩哔哩 → 其他；版本一致后才允许自动替换。
  • 封面与歌词轻点或滑动切换，设置中的显示风格真正驱动播放器。
  • 动态视界使用现有 Folia 渲染器，提供流光、诗行、绘境。用户主动进入横屏，横屏仅留下画面与一条进度控制；返回恢复原页和方向。
  • App 仅显示 Kinara 品牌，来源与许可证保留在仓库与法律材料。

HTML 模拟组件的外观与交互，不能直接代替原生库。候选 Miuix 0.9.4 使用比当前工程更新的 Kotlin/Compose 依赖；确认后先验证完整工具链组合，再逐页迁移。可选模糊模块要求 Android 13，Android 12 保留已有 RenderEffect 方案，不以提高系统门槛换取视觉效果。

流畅度优先解决什么

继续使用 Kotlin/Compose + Media3，先隔离音源解析、音频播放、高频进度与视觉渲染。当前工程已经有并发恢复、700 ms 延迟竞速和独立进度流，需要测量剩余瓶颈，不能假定更换框架就会提速。

现象实施与验证
首播与换源等待记录首个音频帧与各阶段耗时，有限并发、失效源隔离、取消过期任务、预解析下一首。
滚动与控制卡顿观察掉帧和重组，降低高频状态通知，限制封面与模糊采样开销。
动态歌词卡顿/黑屏一个活动渲染器，横竖屏切换尽量复用；可见尺寸与首帧验收，后台暂停视觉。
歌词晚几秒权威音频时钟、seek 后重新锚定，按实际播放版本绑定歌词；避免固定秒数补偿掩盖版本错误。
架构是否要换由 Android 12 真机与较新系统的同机对照结果决定，优先替换已证实的局部瓶颈。

确认之后的顺序

  1. 验证并锁定 Miuix 与工程工具链的兼容组合。
  2. 迁移主题、导航、列表、设置、播放页，再接入主动横屏流程。
  3. 实测音频恢复、样式切换、歌词同步、后台恢复与渲染性能。
  4. 复核签名、升级路径、数据保留与发布内容，再执行确认的上线范围。
